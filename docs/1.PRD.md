# Shadow Heist — Product Requirements Document

## 1. Product summary

Shadow Heist is a two-player confidential strategy game built to demonstrate practical Fully Homomorphic Encryption (FHE) gameplay. Each player secretly chooses one of three actions—Steal, Guard, or Scout. The choices are encrypted before submission, the contract computes the round result without exposing the moves, and the result is revealed only after both players commit.

The product has two modes:

- **Demo mode:** a wallet-free, local simulation used for presentations and product exploration.
- **Live mode:** a Sepolia/FHEVM path with wallet connection, encrypted input submission, on-chain resolution, and public decryption of result handles.

The current repository contains the complete demo UI and the live contract/adapter layer. The final live match state machine still needs to be wired into the React screens.

## 2. Why we are building it

Most blockchain games reveal player intent through public transactions, mempools, or contract state. Shadow Heist demonstrates a different pattern: players can commit strategy without leaking their move before the reveal. It is intentionally small enough to understand quickly, but concrete enough to prove that FHE can support interactive game mechanics instead of only private balances or sealed bids.

The project is also designed as a two-minute technical demo for the Zama confidential gaming program: connect a wallet, create or join a match, commit a move, observe the encrypted processing stages, and reveal the round outcome.

## 3. Goals

1. Make the privacy property understandable without requiring cryptography expertise.
2. Give a new visitor a playable flow within two minutes.
3. Preserve the core game loop: lobby → waiting room → secret action → resolution → revealed result.
4. Keep the visible experience useful without a wallet through demo mode.
5. Provide a credible path to real Sepolia/FHEVM execution.
6. Make the contract and client boundaries easy for contributors to inspect.

## 4. Non-goals for the MVP

- Persistent player accounts or social login.
- Matchmaking, ranking, chat, or a production backend.
- Token rewards, NFTs, or real-money wagering.
- Full multiplayer synchronization in the demo UI.
- A production-grade anti-cheat or dispute system.
- Guaranteed production readiness for the smart contract without a security review.

## 5. Personas

### Curious player
Wants to understand what a confidential game feels like. They should be able to run the demo without installing a wallet.

### Web3 player
Has MetaMask, Rabby, Coinbase Wallet, or a mobile wallet. They want a familiar connect flow and clear Sepolia requirements.

### Protocol evaluator
Wants to inspect the Solidity contract, encrypted input path, ACL permissions, public decryption, tests, and deployment commands.

## 6. Core game rules

Actions are encoded as encrypted `euint8` values:

| Action | Value | Beats | Loses to | Game meaning |
|---|---:|---|---|---|
| Steal | 1 | Scout | Guard | High-risk vault grab |
| Guard | 2 | Steal | Scout | Defensive counter |
| Scout | 3 | Guard | Steal | Information advantage |

Equal actions draw. In the demo, the round event alternates between a Silent Alarm and a Dead Drop Bonus. In the contract, an encrypted random event is generated and used to calculate the encrypted points.

## 7. Primary user journeys

### Explore the game without a wallet

1. Open the home page.
2. Read the three privacy signals and the rules panel.
3. Select **Create a vault**.
4. Use **Simulate rival** in the waiting room.
5. Enter the game.
6. Choose Steal, Guard, or Scout.
7. Press **Seal my move**.
8. Watch the stages: encrypting, submitting, waiting, resolving, and decrypting.
9. Read the revealed actions, event, points, and updated scoreboard.
10. Start the next round or rematch.

### Connect a browser wallet

1. Click **Connect wallet**.
2. Choose **Browser wallet**.
3. Approve the wallet request.
4. If required, switch to Sepolia.
5. The header shows the connected address.

### Connect a mobile wallet

1. Click **Connect wallet**.
2. Choose **WalletConnect**.
3. Scan the QR code in a compatible mobile wallet.
4. Approve the connection.
5. The app validates Sepolia before accepting the session.

WalletConnect requires the public `VITE_WALLETCONNECT_PROJECT_ID` environment variable.

## 8. Functional requirements

- The lobby must explain confidential choices in plain language.
- The wallet button must support injected wallets and WalletConnect QR.
- A wrong network must produce an actionable Sepolia message.
- The lobby must support create and join controls in demo mode.
- The waiting view must show the match code, player seats, and opponent status.
- The round view must prevent submission without a selected action.
- The processing view must show deterministic state labels.
- The result view must reveal both actions, outcome, event text, and points.
- Toast messages must be dismissible and auto-expire.
- The app must remain responsive at mobile widths.
- The live adapter must expose create, join, encrypted submit, resolve, read, and decrypt operations.

## 9. Success metrics

- A first-time visitor reaches a revealed result without documentation.
- A reviewer can find the contract and understand the privacy boundary in under five minutes.
- `pnpm build` passes.
- `pnpm contracts:test` passes.
- A Sepolia two-wallet round can be completed after the live UI wiring slice is finished.

## 10. Open decisions

- Decide whether the contract should store verified plaintext scores after public decryption or keep score aggregation client-side for the first demo.
- Add a second contract test that exercises encrypted inputs with the FHEVM mock utilities.
