# Shadow Heist — Code Style

## 1. General principles

- Prefer small, named functions over deeply nested callbacks.
- Keep product behavior explicit and readable.
- Use strict TypeScript; do not weaken compiler settings to silence an error.
- Keep demo behavior separate from live provider and contract adapters.
- Avoid introducing a dependency for a trivial UI primitive.

## 2. TypeScript and React

- Use `type` imports for type-only symbols.
- Use discriminated unions for finite state such as `MatchView`, `ProcessingState`, and `WalletSource`.
- Keep React component props typed inline or with a nearby exported type when reused.
- Prefer event handlers that read as product actions: `handleCreateMatch`, `handleSubmitAction`.
- Keep side effects in event handlers or `useEffect`; do not perform wallet calls during render.
- Use `void` when intentionally starting an async handler from an event callback.
- Keep wallet and contract code out of presentational components.

## 3. Naming

- Components: PascalCase (`WalletConnectModal`, `GameView`).
- Functions and variables: camelCase (`connectWalletConnect`, `matchCode`).
- Constants: uppercase only for true global constants (`SEPOLIA_CHAIN_ID`).
- Solidity functions: camelCase; events and structs use PascalCase.
- Action names remain lowercase string literals: `steal`, `guard`, `scout`.

## 4. CSS

- Use existing design tokens from `src/styles.css`.
- Prefer class names that describe the role, not appearance alone.
- Keep the noir visual identity consistent: dark surfaces, acid-green primary state, cyan privacy state, orange rival state.
- Preserve focus styles.
- Add responsive rules with the existing breakpoints before creating new ones.
- Avoid inline styles for reusable states.

## 5. Solidity

- Use explicit compiler versions.
- Keep FHE types visible in the contract model.
- Apply ACL permissions whenever encrypted values are stored or reused.
- Emit lifecycle events for indexers and client synchronization.
- Use custom errors in a future cleanup if gas optimization becomes important.
- Document the privacy boundary in NatSpec comments.

## 6. Error handling

- Throw actionable errors at integration boundaries.
- Convert provider errors into concise toast messages at the React layer.
- Do not swallow transaction failures.
- Do not log secrets, proofs, signatures, or private wallet material.

## 7. Dependencies

- Prefer the current `@zama-fhe/sdk` for new FHE client code.
- WalletConnect is lazy-loaded because its QR modal is large.
- Pin or constrain toolchain versions when Hardhat compatibility depends on them.
- Update `pnpm-lock.yaml` with dependency changes.
- Review postinstall/build-script policy changes in `pnpm-workspace.yaml`.

## 8. Commit style

Use short imperative commit messages:

```text
Add WalletConnect wallet chooser
Add encrypted round contract
Document live Sepolia setup
```

A commit should contain one coherent change and pass the relevant build or test command.
