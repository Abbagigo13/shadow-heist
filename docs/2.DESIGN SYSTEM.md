# Shadow Heist — Design System

## 1. Design movement

Shadow Heist uses a **noir cyber-heist** aesthetic: a dark operations console with high-contrast signal colors, sparse editorial typography, and small technical readouts. It should feel like a private mission interface rather than a generic crypto dashboard.

## 2. Brand essence

**Positioning:** A confidential strategy arcade where the best move is the move nobody sees.

**Personality:** Tense, precise, subversive.

**Voice:** Short, concrete, and slightly cinematic. Prefer “Seal your move” over “Submit transaction.” Prefer “Rival detected” over “Opponent connected.”

## 3. Color philosophy

- **Night background:** near-black green establishes secrecy and keeps the interface calm.
- **Acid green:** the signature brand color. It means agency, readiness, and a successful state.
- **Signal cyan:** privacy, cryptographic infrastructure, and system clarity.
- **Warning orange:** opponent activity, risk, and revealed conflict.
- **Muted gray-green:** secondary information that should not compete with the decision.

Primary tokens are defined in `src/styles.css`:

```css
--ink: #f1f2ec;
--muted: #87908a;
--line: rgba(220, 231, 216, .12);
--line-bright: rgba(220, 231, 216, .2);
--acid: #c9f27c;
--cyan: #87d9ca;
--orange: #ff9f5a;
--red: #ff7468;
```

## 4. Typography

- **Space Grotesk:** display headings, product copy, and action labels.
- **DM Mono:** match codes, state labels, network labels, metadata, and technical readouts.

Headings are tight and editorial with negative letter spacing. Mono text is uppercase with tracked spacing for system language.

## 5. Layout principles

- Prefer asymmetric split layouts over centered marketing grids.
- Keep the primary action visually obvious but not oversized.
- Use panels as operational surfaces, not cards floating in empty space.
- Give important transitions their own space: lobby, waiting, and game are separate modes.
- Maintain a generous left edge and use the right side for status, rules, and infrastructure context.

## 6. Signature elements

1. **Vault mark:** a rotated square mark with the vault icon.
2. **Signal rows:** thin rules with icon, title, explanation, and chevron.
3. **Operational readouts:** mono labels such as `SEPOLIA NETWORK`, `FHE READY`, and round state text.
4. **Ambient glows and grain:** subtle background texture that supports the noir atmosphere without reducing contrast.

## 7. Components

- `SiteHeader`: brand, current mode, network status, wallet action.
- `WalletConnectModal`: injected wallet or WalletConnect QR choice.
- `LobbyView`: value proposition, action controls, privacy signals, rules.
- `WaitingView`: match code, seats, progress, simulation control.
- `GameView`: scoreboard, action cards, processing panel, resolution card.
- `Toast`: transient feedback with explicit dismiss control.

## 8. Interaction behavior

- Buttons should visibly respond on hover and keyboard focus.
- Action cards lift slightly on hover and gain a clear acid-green selected state.
- Wallet connection shows a busy label while the provider is initializing.
- Wallet errors appear as concise toasts; never leave the user without feedback.
- The QR option loads its heavy provider bundle only after selection.
- Use `prefers-reduced-motion` to minimize animation for users who request it.

## 9. Responsive behavior

At widths below 720px:

- Hide secondary topbar metadata.
- Collapse lobby, waiting, and game grids into a single column.
- Stack action cards vertically.
- Make the submit button full width.
- Keep the wallet chooser readable with 21px padding and large tap targets.

## 10. Accessibility

- Use semantic buttons for actions.
- Preserve visible focus rings.
- Use `aria-label` for icon-only controls.
- Use `role="dialog"` and `aria-modal="true"` for the wallet chooser.
- Never communicate status by color alone; pair it with text.
- Keep body copy at readable contrast against the dark background.
