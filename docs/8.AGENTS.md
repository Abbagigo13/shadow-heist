# Shadow Heist — Agent and Contributor Guide

## 1. Read first

Before changing behavior, read:

1. `README.md`
2. `docs/1.PRD.md`
3. `docs/3.ARCHITECTURE.md`
4. `CHAIN_INTEGRATION.md`
5. the relevant source file and test

## 2. Source-of-truth map

- Product behavior: `docs/1.PRD.md`
- Visual decisions: `docs/2.DESIGN SYSTEM.md` and `src/styles.css`
- System boundaries: `docs/3.ARCHITECTURE.md`
- Contract privacy behavior: `contracts/ShadowHeist.sol`
- Wallet behavior: `src/chain.ts`
- FHE client behavior: `src/fhevm.ts`
- Live transaction operations: `src/liveGame.ts`
- Demo rules: `src/game.ts`
- React orchestration: `src/App.tsx`

## 3. Development workflow

```bash
pnpm install
pnpm dev
pnpm build
pnpm contracts:compile
pnpm contracts:test
```

Use the existing managed preview. Do not replace the project setup or create a second application entrypoint.

## 4. Safe change boundaries

- Preserve demo mode when adding live mode.
- Keep provider-specific code in `src/chain.ts`.
- Keep Zama SDK calls in `src/fhevm.ts`.
- Keep contract transactions in `src/liveGame.ts`.
- Do not put private keys or user secrets in source.
- Do not log plaintext actions before the intended reveal boundary.
- Update the relevant documentation when a boundary changes.

## 5. When adding a feature

1. State the user-visible outcome.
2. Identify whether it belongs in demo state, wallet state, FHE adapter, contract, or styling.
3. Update the PRD if the product contract changes.
4. Add or update tests.
5. Run the focused check and then the full build.
6. Update README or integration notes if setup changes.

## 6. Review questions

- Does this accidentally reveal a player action early?
- Does this confuse demo simulation with a mined transaction?
- Does the wrong wallet/network produce a clear error?
- Does the new dependency justify its bundle and maintenance cost?
- Is the mobile experience still usable?
- Are the new states represented by explicit types?
- Does the contract enforce the invariant, or is it only enforced by the UI?

## 7. Definition of done

A change is complete when:

- source is readable and typed;
- relevant docs are updated;
- `pnpm build` passes;
- contract changes pass compile and tests;
- no secrets or generated artifacts are committed;
- the project remains explorable without a wallet unless the feature explicitly requires live mode.
